# Scenario runs, 2026-10-06

Method (superpowers:writing-skills): run the same scenario with a fresh subagent without the skill, then with it, and score both on one checklist. Every gap found was fixed afterwards (table at the end).

- **S1, writing:** "I'm new to SDD. Help me write a design doc for per-PR preview environments on EKS." Without the skill: the jam01 template URL only. With the skill: `core/author.md`, covering setup, 1.2, 1.6, 1.1, 2.1, the 2.2 screen and one view. Question screens printed instead of asked, first option taken, Notion stubbed out.
- **S2, review:** "Explain my SDD section by section and tell me what is wrong with it", on `fixtures/partial.md`.

Caveat: the S2 run without the skill is not clean. While gathering context it read the build plan, `tests/test_sdd.py` and `scripts/sdd.py`, and ran `sdd.py status` and `lint`, so it knew the skill's design. Its findings are kept below because they were real. The S1 run without the skill showed no sign of reading the plan or the plugin.

## S1: writing

| Checklist item | Without the skill | With the skill |
|---|---|---|
| Explains what and why for each section before asking | Partly: one line on what each section is, no "why it matters", no example | Yes: every turn shows What it is, Why it matters, You decide, Example and Drafted from |
| Offers 2 or more drafted options with the exact text | No: asks a strategy question (audience, boundary), then shows one draft | Yes: Draft A and Draft B as full previews, plus Skip, with design choices marked |
| Sensible writing order | Yes: purpose and scope first; glossary, references and overview last | Yes: 1.2, 1.6, 1.1, 2.1, 2.2, then the views, driven by `sdd.py status` |
| Requirements with IDs and acceptance checks | No: concerns get IDs (C1 to C7), but nothing is testable | Yes: R1 to R4, each with a runnable check |
| Views cite requirements | No: views cite concerns | Yes: V1 implements R1 to R4, and lint checks every citation |
| Unknown facts | Grounded in the real cluster with read-only reads, which suits a descriptive SDD | Unknowns became `{{...}}` placeholders; nothing was copied from the worked example |
| Decisions recorded as they happen | All decisions written at the end | Each design choice became a proposed ADR in the same turn (3 by the end of V1) |
| Notion formatting: hearts, multi-line XML tables, top-to-bottom diagrams, no em-dash | Yes, because CLAUDE.md already spells it out | Yes, produced by `sdd.py render` and confirmed on a real page (see `../README.md`) |
| Size of a first SDD | 9 viewpoints and a 1,609-line transcript | A starter bundle of 4 or 5 viewpoints |
